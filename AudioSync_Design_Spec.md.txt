AudioSync - System Design Specification
1. Executive Summary
AudioSync is a multi-tenant, self-hosted web application designed to synchronize Audible libraries to a local S3-compatible storage system (MinIO). It enables users to link their Audible accounts, automatically download and decrypt audiobooks, and manage access within a "Family" structure.
Key Features:
* Multi-tenancy: Support for multiple families, each with multiple users.
* Automated Sync: Scheduled background jobs using audible-cli.
* Deduplication: Downloads book assets once, regardless of how many users own them.
* Sharing: Granular controls for sharing books between family members.
* Format: Decrypts .aax to open .m4b formats.
2. Technology Stack
* Language: Python 3.11+
* Web Framework: FastAPI (Async support is crucial for I/O heavy apps)
* Database: PostgreSQL (Metadata, User Auth, Encrypted Credentials)
* ORM: SQLAlchemy (Async) + Alembic (Migrations)
* Task Queue: Celery (with Redis as Broker)
* Storage: MinIO (S3 Compatible Object Storage)
* Audible Interface: audible-cli (wrapped via subprocess or internal library usage)
* Audio Processing: FFmpeg (for decryption/transcoding)
3. System Architecture
3.1 Container Services (Docker Compose)
The application will be deployed as a set of containerized services:
1. api: FastAPI application serving the REST endpoints and UI.
2. worker: Python/Celery worker. Contains audible-cli, ffmpeg, and the sync logic.
3. db: PostgreSQL 16.
4. redis: Message broker for Celery.
5. minio: Local S3 storage.
3.2 Data Flow
1. Auth Link: User authenticates via API -> auth.json generated -> Encrypted -> Stored in Postgres.
2. Sync Trigger: Schedule/Manual -> Celery Task dispatched.
3. Sync Execution: Worker fetches auth.json -> Decrypts to temp file -> Runs audible-cli -> Downloads/Decrypts book -> Uploads to MinIO.
4. Consumption: User requests book -> API checks family & is_shared permissions -> API generates Presigned S3 URL -> User streams/downloads.
4. Database Schema (PostgreSQL)
Table: families
Groups users together for sharing context.
* id (UUID, PK)
* name (String)
* created_at (Timestamp)
Table: users
Application login credentials (not Audible credentials).
* id (UUID, PK)
* family_id (UUID, FK -> families.id)
* username (String, Unique)
* hashed_password (String)
* role (Enum: ADMIN, MEMBER)
Table: audible_profiles
Stores the sensitive connection to Audible.
* user_id (UUID, FK -> users.id, PK)
* encrypted_auth_json (Binary/LargeBinary) - AES-256 Encrypted
* activation_bytes (String) - Required for decryption
* locale (String) - e.g., 'us', 'uk', 'de'
* last_sync_status (Enum: SUCCESS, FAILED, RUNNING)
* last_sync_time (Timestamp)
Table: books
Global catalog of downloaded assets (Deduplicated).
* asin (String, PK) - The Audible Unique ID
* title (String)
* author (String)
* cover_image_path (String) - Path in S3
* audio_file_path (String) - Path in S3 (Decrypted .m4b)
* duration (Integer) - Seconds
* size_bytes (BigInt)
Table: library_items
Links users to books. Represents "Ownership".
* id (UUID, PK)
* user_id (UUID, FK -> users.id)
* book_asin (String, FK -> books.asin)
* is_shared (Boolean) - Default False. If True, visible to family.
* purchase_date (Timestamp)
5. Security Implementation
5.1 Credential Storage
The auth.json file generated by audible-cli contains session tokens. This must never be stored in plain text.
* Method: Symmetric Encryption (Fernet / AES).
* Key Management: The encryption key should be stored as an Environment Variable (ENCRYPTION_KEY) injected into the Docker container, not in the database.
5.2 Worker Sandboxing
When the Celery worker runs a sync:
1. Create a temporary directory: /tmp/sync_{task_id}/.
2. Decrypt auth.json from DB -> Write to /tmp/sync_{task_id}/auth.json.
3. Execute audible-cli using --config /tmp/sync_{task_id}/audible.toml.
4. CRITICAL: Upon task completion (success or failure), the entire /tmp/sync_{task_id}/ directory is recursively deleted to ensure no tokens persist on disk.
6. The Sync Engine Workflow (Python/Celery)
Task Name: tasks.sync_user_library(user_id)
1. Initialization:
   * Fetch audible_profile for user_id.
   * Decrypt auth.json.
   * Initialize audible.Client (or CLI wrapper).
2. Manifest Retrieval:
   * Fetch user's library list from Audible API.
   * Filter out items already in library_items table for this user.
3. Asset Processing (Loop through new items):
   * Check Global Cache: Does this ASIN exist in the books table with a valid S3 path?
      * Yes: create library_item entry immediately. Skip download.
      * No (Download Required):
         1. Download .aax / .aaxc to temp folder.
         2. Extract activation_bytes (if not already saved).
         3. Decrypt: Run ffmpeg -activation_bytes {bytes} -i input.aax -c copy output.m4b.
         4. Download Cover Art.
         5. Upload: Push .m4b and .jpg to MinIO.
         6. DB Update: Create row in books and library_items.
         7. Cleanup: Delete temp files for this book.
4. Finalization:
   * Update audible_profile.last_sync_time.
   * Securely wipe auth files.
7. API Endpoints
Authentication (App)
* POST /token: Login to AudioSync (OAuth2 standard).
Audible Connection
* POST /audible/register: Initiates the login flow (returns a code/URL).
* POST /audible/callback: Submits the 2FA code/response to generate auth.json.
Library Management
* GET /books: List books.
   * Query Param: scope=mine (default) vs scope=family.
   * Logic: If scope=family, return My Books + (Family Books where is_shared=True).
* GET /books/{asin}/stream: Returns a Presigned S3 URL for the .m4b file.
* PATCH /books/{asin}/sharing: Toggle is_shared status.
System
* POST /sync: Manually trigger a background sync for the current user.
* GET /tasks/{task_id}: Check status of a running sync.
8. S3 Bucket Structure
We use a "Flat" structure for assets to maximize deduplication.
bucket-name/
├── assets/
│   ├── {asin}.m4b       # Decrypted Audio
│   └── {asin}.jpg       # Cover Art
└── backups/
   └── {user_id}/       # (Optional) Raw metadata backups
